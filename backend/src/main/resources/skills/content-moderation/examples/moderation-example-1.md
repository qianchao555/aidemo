# 内容审查示例 1：安全审查与敏感词处理

## 场景
某社区平台需要对用户评论进行上线前的安全审查，确保不包含违规内容。

## 对话过程

**用户**：帮我检查一下这条用户评论是否有问题：「这个产品太垃圾了，客服态度极差，简直就是个骗子平台！大家千万别上当！！！」

**Agent 分析**：
- 审查目标：用户评论安全审查
- 严格程度：medium（公开社区标准）
- 需关注的维度：情绪化表达、攻击性语言、煽动性号召

**Agent 审查结论**：

```markdown
审查结论：需复核 (review)
风险等级：medium
违规类型：负面情绪表达、可能涉及名誉损害

详细发现：
1. 全文情绪化表达强烈，包含攻击性言辞（"垃圾"、"骗子"）
   → 建议引导用户以更客观的方式表达不满，保留事实性投诉内容
2. "大家千万别上当"为煽动性号召
   → 可能引发群体负面效应，建议修改为个人观感表达
```

**用户**：保留评论意图但去除敏感表达，用 suggest 模式处理。

**Agent 处理**：
```
原文：这个产品太垃圾了，客服态度极差，简直就是个骗子平台！大家千万别上当！！！
替换：该产品未能达到我的预期，客服响应速度和服务态度有待提升，整体体验不够理想。建议大家购买前多方了解。
```

## 关键启示
- medium 严格度下，情绪化但未违法的内容标记为"需复核"而非直接拒绝
- suggest 模式保留用户意图（表达不满），同时去除攻击性语言
- 审查应区分"事实性投诉"和"情绪化攻击"，前者应有表达空间
